What Happens When You Build Tech for Communities Instead of Consumers

Jonathan Barlow Life Engineer
June 6, 2026 4 min read

The average consumer app loses 77% of its users within three days, according to Localytics data. But apps built for communities — not consumers — show retention rates above 60% after six months. The difference isn't in the code. It's in who defines the problem and how success gets measured.

Communities Have Problems, Consumers Have Preferences

Consumer tech optimizes for engagement and extraction. Community tech optimizes for connection and coordination. When we build for consumers, we're solving for individual convenience. When we build for communities, we're solving for collective capacity.

Detroit's neighborhood block clubs needed a way to track vacant properties and coordinate cleanup efforts. The consumer approach would have been a slick property-scouting app with photo filters and social sharing. Instead, local developers built Motor City Mapping — a simple tool that let residents document conditions block by block, creating a shared database that informed city policy.

The technical requirements looked completely different. No viral loops or push notifications. Just reliable data collection, clear visualization, and integration with existing city systems. The app didn't need to scale globally. It needed to work reliably for 15,000 residents documenting 80,000 properties.

Infrastructure vs. Engagement

Consumer tech companies measure daily active users and time spent in-app. Community tech measures whether the infrastructure works when people need it. The metrics tell different stories about success.

Barcelona's Decidim platform processes over 10,000 citizen proposals annually across 300+ organizations worldwide. The software doesn't track how long people spend scrolling through proposals. It tracks how many proposals advance to implementation and how many residents participate in final decisions.

Austin's community resilience networks use mesh networking technology to maintain communication during disasters. Success isn't measured in engagement rates — it's measured in neighborhoods that stay connected when centralized infrastructure fails. The technology stays invisible until it becomes essential.

Consumer platforms extract value by controlling data and user relationships; community platforms create value by distributing control and building local capacity.

Who Controls the Stack

Consumer platforms extract value by controlling data and user relationships. Community platforms create value by distributing control and building local capacity. The technical architecture reflects these different priorities.

Community-focused platforms typically use open-source frameworks, store data locally, and design for interoperability rather than lock-in. Users can export their data, modify the software, and run their own instances. This isn't just ideological — it's practical. Communities need tools they can maintain independently.

Detroit's Code for America brigade maintains several civic applications using this approach. When the city's IT priorities shift or budgets get cut, the tools keep running. The community owns both the code and the operational knowledge to maintain it.

Scale Differently

Consumer tech scales through network effects and viral growth. Community tech scales through replication and federation. Instead of one massive platform serving millions, you get many connected instances serving thousands.

Mastodon exemplifies this approach — over 12,000 independent servers connecting 14+ million users worldwide. Each community runs its own instance with its own rules, while still connecting to the broader network. Local control with global connectivity.

This changes the economics entirely. No venture capital seeking 100x returns. No advertising-driven business model optimizing for attention. Just sustainable technology serving specific communities with specific needs. The software gets better through use, not through user acquisition.

What We're Building Toward

The community approach creates different incentives for developers and different outcomes for users. Instead of optimizing for addiction, we optimize for agency. Instead of extracting attention, we build attention spans. Instead of harvesting data, we help communities generate their own insights.

This doesn't mean community tech can't be sophisticated or profitable. It means the sophistication serves coordination rather than manipulation, and profitability comes from value creation rather than value extraction.

The technical patterns are well-established: federation instead of centralization, open protocols instead of walled gardens, community ownership instead of platform dependency. What's missing is the institutional infrastructure to support this approach at scale.

The choice between building for consumers versus communities isn't just about technology — it's about power distribution and long-term sustainability. Every system we build either concentrates control or distributes it. Every platform either extracts from communities or invests in them. The code is political, whether we acknowledge it or not. The question is what kind of politics we're programming into the world.
